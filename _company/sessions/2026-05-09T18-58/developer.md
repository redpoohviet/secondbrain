#### 1. KPI 추출 모듈 실행 환경 검증 (Execution Environment Check)

**목표:** 제공된 인증 정보가 `pipeline_verifier.py`의 모든 API 호출에 대해 유효한지, 그리고 필요한 라이브러리 및 환경 변수가 올바르게 설정되었는지 확인합니다.

*   **검증 항목:**
    1.  **인증 정보 유효성 검사:** YouTube API 키와 채널 ID가 환경 변수 또는 코드 내에서 예상되는 형식과 일치하는지 확인합니다. (API 키 노출 방지 원칙 준수)

    3.  **데이터 접근 권한 점검:** API 키의 범위(Scope)가 KPI 추출에 필요한 데이터(시청 시간, 이탈 지점 등)에 접근할 수 있도록 설정되었는지 내부 로직을 검증합니다.

#### 2. 데이터 수신 오류 처리 시나리오 준비 (Error Handling Scenarios)

**목표:** 데이터 파이프라인 중 발생 가능한 주요 오류 지점(API 제한, 데이터 형식 불일치, 네트워크 오류 등)에 대한 구체적인 대응 계획을 수립합니다.

*   **시나리오 1: API Rate Limiting (E-02)**
    *   **발생 조건:** 짧은 시간 내에 과도한 API 요청이 발생하여 제한에 걸리는 경우.
    *   **대응 전략:** `try...except` 블록 내에서 HTTP 상태 코드(429)를 명시적으로 포착하고, 지연 시간(Backoff)을 적용하여 최대 재시도 횟수(Max Retries)를 설정합니다.
*   **시나리오 2: 데이터 형식 불일치 (E-01)**
    *   **발생 조건:** API로부터 수신된 JSON 응답의 키 또는 데이터 타입이 예상되는 스키마와 일치하지 않는 경우.
    *   **대응 전략:** 데이터 로드 직후, 수신된 데이터를 `try...except`로 감싸고, 스키마 검증 함수를 호출하여 불일치 항목을 플래그(`error_log.json`)에 기록하고 파이프라인을 중단(Fail)시킵니다.
*   **시나리오 3: 인증 실패 (Auth Failure)**
    *   **발생 조건:** API 키가 만료되었거나 권한이 부족하여 요청이 거부되는 경우.
    *   **대응 전략:** 초기화 단계에서 인증 정보를 검증하고, 실패 시 즉시 `pipeline_verifier` 모듈을 비활성화하며 시스템 로그에 '인증 오류'를 기록하고 사용자에게 알림을 발생시킵니다.
